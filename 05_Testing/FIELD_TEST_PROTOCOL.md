# Field Test Protocol

## Purpose

This document outlines the standardized process for testing prototypes in real workshop conditions. Consistent testing allows us to compare solutions objectively and make data-driven decisions.

---

## Pre-Test Phase

### Selection of Test Sites

**Criteria for selection**:
- [ ] Representative of typical workshops (size, layout, equipment)
- [ ] Owner willing to participate and provide feedback
- [ ] Can accommodate test duration (2-4 weeks minimum)
- [ ] Safe environment for prototype installation
- [ ] Accessible for weekly monitoring visits

**Number of test sites**: 3-5 workshops minimum per prototype

---

### Baseline Data Collection

**Before installing prototype, collect**:

#### Environmental Measurements
- Room dimensions (L × W × H)
- Number and position of looms
- Ventilation (doors, windows, existing fans)
- Temperature and humidity
- Light levels
- Photos/videos of current conditions

#### Lint Assessment
- Visual lint accumulation (0-5 scale) on:
  - Machines (gears, frames, moving parts)
  - Ceiling and walls
  - Floor
  - Fabric being produced
- Airborne lint density (visual assessment)
- Time spent on daily cleaning
- Frequency of machine jams/issues

#### Worker Health & Comfort
- Number of workers exposed
- Self-reported symptoms (coughing, eye irritation, throat issues)
- Use of protective equipment
- General satisfaction with workspace (1-10 scale)

#### Productivity Metrics
- Daily production volume (meters of fabric)
- Downtime for cleaning/maintenance (minutes per day)
- Fabric defect rate (if trackable)
- Worker attendance

**Baseline Data Collection Period**: 1 week before installation

---

## Testing Phase

### Duration
**Minimum**: 2 weeks  
**Recommended**: 4 weeks  
**Extended** (if needed): 6-8 weeks

### Monitoring Schedule

#### Daily (Worker/Owner Self-Reporting)
- Prototype operational: [ ] Yes [ ] No
- If no, reason: _______________________
- Any problems noticed: _______________________
- Operating hours: _______ hours

**Provide simple daily log sheet to owner**

#### Weekly (Researcher Site Visit)

**Prototype inspection**:
- [ ] Operating correctly
- [ ] Physical condition (any damage/wear)
- [ ] Filter/component condition (if applicable)
- [ ] Maintenance performed as scheduled
- [ ] Unusual noises or behaviors

**Environmental measurements**:
- Lint accumulation assessment (same locations as baseline)
- Photos/videos for comparison
- Temperature/humidity (if relevant)

**Stakeholder interviews**:
- Brief check-in with owner (5-10 min)
- Brief check-in with 2-3 workers (5 min each)
- Any concerns or observations

#### Bi-weekly (Detailed Assessment)

**Performance data**:
- Lint reduction visual comparison (before/after photos)
- Worker satisfaction survey (structured questions)
- Production data review (if owner tracks)
- Maintenance time logged

## Quantitative Metrics

### Primary Metric: Lint Reduction

**Visual Assessment Method**:
- Take photos from same angle/distance each week
- Rate 0-5 for each location
- Calculate average across all locations
- Compare to baseline

**Target**: ≥50% reduction

### Secondary Metrics

**Health Impact**:
- % of workers reporting reduced coughing
- % reporting reduced eye irritation
- Overall comfort score improvement

**Productivity Impact**:
- Change in daily cleaning time (minutes)
- Change in machine jam frequency
- Change in daily production (if measurable)

**User Satisfaction**:
- Average satisfaction score (1-10)
- % who would continue using solution
- % who would recommend to others

## End-of-Test Phase

### Final Data Collection

**At end of test period**:

1. **Complete final lint assessment** (same as weekly)
2. **Conduct detailed stakeholder interviews**
3. **Review all logged data**
4. **Take comprehensive before/after photos**
5. **Calculate all metrics**
6. **Collect prototype for inspection**

### Final Interviews

**Workshop Owner** (30 minutes):

1. Overall experience with the prototype?
2. Did it meet your expectations?
3. What worked well?
4. What didn't work well?
5. Would you pay [cost] for this solution?
6. Would you recommend it to others?
7. What improvements would make it better?
8. Would you like to keep using it?

**Workers** (15 minutes each, interview 3-5):

1. Did you notice a difference in air quality?
2. Did you have any health improvements?
3. Did it make your work easier or harder?
4. Was it easy to maintain?
5. Any complaints or problems?
6. Would you want this in your workshop permanently?

## Reporting

### Test Report Outline

1. **Executive Summary**
   - Prototype tested
   - Number of sites
   - Duration
   - Key results (lint reduction %, user satisfaction)
   - Recommendation (proceed/iterate/abandon)

2. **Methodology**
   - Test sites description
   - Data collection methods
   - Testing duration and schedule

3. **Results**
   - Quantitative metrics (tables, graphs)
   - Qualitative feedback (quotes, themes)
   - Before/after photos

4. **Discussion**
   - What worked well
   - What didn't work
   - Unexpected findings
   - Limitations of the test

5. **Recommendations**
   - Design improvements needed
   - User training needs
   - Installation modifications
   - Next steps

6. **Appendices**
   - Raw data
   - All interview transcripts
   - Photo documentation

## Success Criteria

### Test is considered successful if:

**Must meet**:
- [ ] Average lint reduction ≥ 50%
- [ ] No safety incidents
- [ ] ≥70% of users report satisfaction ≥7/10
- [ ] ≥60% of users want to continue using it

**Should meet** (2 of 3):
- [ ] Average lint reduction ≥ 70%
- [ ] Measurable productivity improvement
- [ ] ≥80% user satisfaction

**Nice to have**:
- [ ] Cost under budget
- [ ] Minimal maintenance issues
- [ ] Workers report health improvements
- [ ] Owners willing to pay for solution

---

## Post-Test Actions

### If Test is Successful
1. Document final design specifications
2. Plan refinements based on feedback
3. Prepare for scaling to pilot phase
4. Create user manuals and training materials

### If Test Shows Promise but Needs Improvement
1. Identify specific issues to address
2. Design iteration plan
3. Build improved prototype (v2)
4. Plan follow-up testing

### If Test Fails
1. Conduct failure analysis
2. Determine if concept is salvageable
3. Document lessons learned
4. Consider alternative concepts
