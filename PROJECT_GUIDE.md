## How to Use This Structure

### If You're Just Starting

1. **Read the README.md** - Get project overview
2. **Read PROJECT_ROADMAP.md** - Understand the phases
3. **Read PROBLEM_STATEMENT.md** - Understand the problem deeply
4. **Read INITIAL_EVIDENCE.md** - See what we know so far

### If You're Doing Research

1. Use **INTERVIEW_TEMPLATE.md** for stakeholder interviews
2. Use **FIELD_OBSERVATION_TEMPLATE.md** for workshop visits
3. Save completed forms in `02_Problem_Research/Interviews/` and `02_Problem_Research/Observations/`
4. Update **PROBLEM_STATEMENT.md** with new insights

### If You're Brainstorming Solutions

1. Read **IDEATION_FRAMEWORK.md** for brainstorming techniques
2. Document ideas in `03_Solution_Ideation/Ideas/`
3. Use **EVALUATION_FRAMEWORK.md** to score and compare
4. Record decisions in `03_Solution_Ideation/Selected_Concepts/`

### If You're Building Prototypes

1. Use **PROTOTYPE_DOCUMENTATION_TEMPLATE.md**
2. Document build process with photos (store in `08_Assets/Photos/Prototype_Photos/`)
3. Track costs and materials
4. Save all documentation in `04_Prototypes/[PrototypeName]/`

### If You're Testing Solutions

1. Follow **FIELD_TEST_PROTOCOL.md** exactly
2. Collect data systematically
3. Save test results in `05_Testing/[PrototypeName]/`
4. Take before/after photos (store in `08_Assets/Photos/Before_After/`)

### If You're Writing Documentation

1. Use **USER_MANUAL_TEMPLATE.md** as starting point
2. Include diagrams and photos
3. Test instructions with real users
4. Save final versions in `06_Documentation/`

### If You're Analyzing Costs

1. Use **COST_ANALYSIS_TEMPLATE.md**
2. Track all expenses
3. Calculate ROI and payback period
4. Save analyses in `07_Business/`

## Weekly Workflow

### Monday
- Review **WEEKLY_CHECKLIST.md** from last week
- Set goals for current week
- Update **PROJECT_ROADMAP.md** if milestones changed

### During the Week
- Complete planned tasks
- Document everything
- Take photos and videos
- Update daily sections in **WEEKLY_CHECKLIST.md**

### Friday
- Complete weekly review section in **WEEKLY_CHECKLIST.md**
- Plan next week's tasks
- File completed checklist in `01_Project_Plan/Weekly_Checklists/`
- Update **README.md** with current status

## Documentation Best Practices

### Always Document

- **What** you did
- **Why** you did it
- **What** you learned
- **What's** next

### Use Templates

We have templates for most activities - use them! They ensure consistency and completeness.

### Take Photos

- Before starting
- During the process
- After completing
- Problems encountered
- Close-ups of important details

### Name Files Clearly

Follow naming conventions in `08_Assets/README.md`

### Version Control

- Add version numbers to documents (v01, v02, etc.)
- Note what changed between versions
- Keep previous versions for reference

## Project Phases at a Glance

### Phase 1-2: Research (Weeks 1-6)
**Focus**: Understand problem deeply  
**Key docs**: Problem Statement, Interviews, Observations  
**Outcome**: Validated problem definition

### Phase 3-4: Ideation (Weeks 7-10)
**Focus**: Generate and evaluate solutions  
**Key docs**: Ideation Framework, Evaluation Framework  
**Outcome**: 2-3 selected concepts

### Phase 5-6: Prototyping (Weeks 11-18)
**Focus**: Build and test prototypes  
**Key docs**: Prototype Documentation, Field Test Protocol  
**Outcome**: Working prototypes with data

### Phase 7-8: Refinement (Weeks 19-22)
**Focus**: Improve design, create documentation  
**Key docs**: User Manual, Cost Analysis  
**Outcome**: Production-ready design

### Phase 9-10: Scale (Weeks 23+)
**Focus**: Deploy and expand  
**Key docs**: Implementation plans, case studies  
**Outcome**: Impact at scale

## Remember

### Core Principles

1. **User-Centered**: Everything should serve workshop owners and workers
2. **Practical**: Solutions must be affordable and implementable
3. **Documented**: If it's not documented, it didn't happen
4. **Iterative**: Expect to fail, learn, and improve
5. **Collaborative**: Better together

### Project Values

- **Empathy**: Deep understanding of users
- **Rigor**: Systematic, data-driven approach
- **Creativity**: Open to diverse solutions
- **Practicality**: Focus on what works
- **Impact**: Aim for meaningful change
